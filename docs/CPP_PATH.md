# C++ 伪代码与单文件编译路径

> AutoClicker v1.4 · 高级版规划文档
> 由 Luo-Jacob 制作 · MIT License

本目录给出两样东西：

| 文件 | 作用 |
| --- | --- |
| `clicker.cpp` | 一个**可直接编译**的 Win32 单文件骨架。只依赖 `user32`，无需 DLL、无需运行时安装包、无需第三方库。用户只改 `user_code()`。 |
| `CPP_PATH.md` | 本文：内置接口对照、编译命令、体积对比，以及「数据包级点击模拟」的设计规划。 |

主程序（Python + tkinter 打包的 `AutoClicker.exe`）里已经内置了同一套**类 C 伪代码 DSL**，
在「设置 → 高级」开启后即可编写、语法检查并运行；本文档是把它落到原生 C++ 单文件的路径。

## 1. 内置接口对照（无头文件）

用户代码不需要写任何 `#include`。下表左右两侧写法一致，方便把 GUI 里的脚本直接搬到 C++。

| 函数 | 必填参数 | 说明 | GUI DSL | C++ 骨架 |
| --- | --- | --- | --- | --- |
| `rand(seed)` | 否 | 返回 10⁴~10⁵ 的随机数；`seed` 作随机种子 | ✅ | ✅ |
| `left(坐标)` | 否 | 左键点击；不填 = 跟随当前鼠标 | ✅ | ✅ |
| `right(坐标)` | 否 | 右键点击 | ✅ | ✅ |
| `middle(坐标)` | 否 | 中键点击 | ✅ | ✅ |
| `keyboard(*按键)` | ✅ | 按下按键，如 `"A"` / `"Ctrl+Shift+F5"` / `"Enter"` | ✅ | ✅ |
| `pause(*ms)` | ✅ | 等待 n 毫秒，可被急停立即打断 | ✅ | ✅ |
| `hotkey(*按键)` | ✅ | GUI 里首行用于**声明启动热键**；C++ 里注册全局热键 | ✅ | ✅ |
| `mouse()` | — | 返回当前鼠标坐标，可取 `.x` / `.y` | ✅ | ✅ |
| `point(x, y)` | ✅ | 构造一个坐标（C++ 里用 `Coord` / 直接 `left(x, y)`） | ✅ | ✅（重载） |

`*` 为必填参数。坐标的四种写法：

```c
left();                 // 跟随鼠标
left(mouse());          // 取当前鼠标位置
left(point(320, 240));  // GUI DSL 的写法
left(320, 240);         // C++ 骨架的重载写法
```

### 可用语法

```
int a, b = 10;
for (i = 0; i < 10; i++) { ... }
while (1) { ... }
if (a > b) { ... } else { ... }
break;  continue;
a++;  a--;  a += 2;  a *= 3;
+ - * / %   == != < <= > >=   && || !   ( )
```

GUI 的 DSL 解释器额外提供：`a.x` 属性访问、`while` / `for` 的步数上限、
以及随时可中断的 `pause()`。它**没有**文件读写、网络、模块导入、指针和任意函数定义能力。

## 2. 编译成单文件 exe

### MSVC（Developer Command Prompt for VS）

```bat
cl /O2 /MT /EHsc /DUNICODE /D_UNICODE clicker.cpp /link user32.lib /out:clicker.exe
```

`/MT` 静态链接 CRT，避免依赖 `vcruntime*.dll`。

### MinGW-w64

```bat
g++ -O2 -s -static -mwindows clicker.cpp -luser32 -o clicker.exe
```

`-static` 静态链接 libgcc/libstdc++，`-s` 去符号，`-mwindows` 不弹控制台。

### 产物对比

| 方案 | 单文件 | 额外依赖 | 典型体积 |
| --- | --- | --- | --- |
| `clicker.cpp`（MSVC `/MT`） | ✅ | 无 | 约 100–200 KB |
| `clicker.cpp`（MinGW `-static -s`） | ✅ | 无 | 约 50–120 KB |
| 主程序 `AutoClicker.exe`（Python + PyInstaller onefile） | ✅ | 无（已打包） | 约 31 MB |

> 手写稿里的「≤5 MB / zip≤5 MB / 精简核心 ≤2 MB」目标，Python 路线达不到；
> 但 C++ 骨架远低于该目标。主程序保留 GUI / 托盘 / 主题 / 配置 / 三套运行模式，
> C++ 骨架则面向「只需一段点击逻辑、要极小体积」的场景，两者互补而非替代。

### 从 GUI 脚本迁移到 C++

1. 在「脚本编辑器」写好并**语法检查**通过。
2. 复制 `user_code()` 之外的部分不动，只把脚本内容粘进 `user_code()`。
3. 把 `point(x, y)` 改成 `Coord c = {x, y};` 或直接 `left(x, y)`。
4. 把首行 `hotkey("...")` 保留（C++ 里它会注册全局热键）。
5. 按上面命令编译；`Ctrl+Alt+F12` 是常驻急停。

## 3. 技术实现：基础版 vs 高级版

### 基础版（已实现）

`SendInput` + `MOUSEINPUT` / `KEYBDINPUT`，与真人操作走同一条系统输入链路；
`GetCursorPos` / `SetCursorPos` 实现坐标拾取与固定坐标点击（可选点击后恢复光标）；
`RegisterHotKey` + 低层键盘钩子实现全局热键与最多 5 键组合；
`Event.wait` 做可中断节拍，`hold` 也改为可中断等待，急停立即生效。

### 高级版：数据包级点击模拟（**仅规划，本期不实现**）

「数据包级」指绕开系统输入队列，直接在更下层产生事件。可行路径与代价：

| 路径 | 做法 | 代价 / 风险 |
| --- | --- | --- |
| 过滤驱动 | 自写 HID/键盘类过滤驱动，向设备栈注入报告 | 需要驱动签名、管理员权限、蓝屏风险、维护成本极高 |
| 虚拟 HID 设备 | 用 UMDF / ViGEm 等创建虚拟设备，由系统当作真实硬件 | 需要安装驱动，与「零额外依赖」目标冲突 |
| 协议层 | 针对特定协议（如 adb、远程桌面、网络输入协议）直接发包 | 只对特定目标有效，不是通用 Windows 点击 |
| 内核回调注入 | 直接调用未文档化的输入栈内部函数 | 版本强相关、稳定性差、易被安全软件拦截 |

**不实现的原因**：

1. 与「单文件、无额外依赖、免安装」目标根本冲突 —— 前两条路径都要装驱动。
2. 需要内核签名与管理员权限，普通用户无法直接运行。
3. 这类能力常被用于绕过反作弊 / 自动化风控，分发的合规与误用风险高。
4. 对绝大多数使用场景，`SendInput` 已经是系统级物理输入，效果等价且稳定。

因此本期把「数据包级」限定为**设计规划**，只在此文档记录技术路线与取舍，
不提供代码、不提供驱动、不提供绕过机制。基础版保持系统级模拟点击。

> 补充说明：v1.4 的「单轮时长」在 GUI 里指**单个节点本轮的持续时间上限**（`round_duration_ms`），
> 到时立即结束该节点并进入下一节点；与流程级的「总时长」结束条件是不同层级、互不相等的参数。

## 4. 已知限制

- 仅支持 Windows（`SendInput` / `RegisterHotKey` / 系统托盘）。
- 以管理员权限运行的程序可能收不到普通权限进程的注入输入，请让两者权限级别一致。
- 固定坐标点击会短暂移动物理光标；多个动作并行且各设不同坐标时会争用同一个系统光标，
  骨架里用「点击后立即恢复」缓解，但无法完全消除。
- 无修饰键的单键热键会全局独占该按键，建议使用组合键。
- 本机开发环境未安装 MSVC / MinGW，`clicker.cpp` 只做了静态审阅，**未实测编译**；
  编译时若报错，多半是 SDK 版本或入口点差异，按编译器提示微调即可。
